# AI 应用 / Agent 开发岗位简历填写框架

本项目源自 [bcefghj/multi-agent-ecommerce-system](https://github.com/bcefghj/multi-agent-ecommerce-system)。本页用于核对和组织个人经历，**不是可以直接复制的项目成果**。只写自己确实完成、能展示代码和解释取舍的部分；把上游原有功能、学习过程与个人改造分开说明。

当前新增 Python 导购框架的实际范围和复现步骤见 [Python 导购 Agent 框架](../python/SHOPPING_AGENT.md)。项目使用合成商品与代理编写的离线标签；没有真实商品授权、真人标注、生产负载或线上 CTR／GMV 数据。

## 可核对的证据与写法

| 可以写的内容 | 核对位置 | 表述边界 |
|---|---|---|
| LangGraph 条件路由与角色分工 | `python/shopping_agent/workflow.py`、`agent_roles.py` | 说明自己的改动；不要把上游三语言实现都算作个人工作 |
| 商品／FAQ 来源、当前库存与版本复核 | `storage.py`、`catalog_cli.py`、相关测试 | 只说明本地 SQLite 原型，不称生产库存服务 |
| BM25、向量、混合检索及来源证据 | `retrieval.py`、`evaluation.py` | 默认向量基线是 hash surrogate，不称真实语义检索效果 |
| 多商品完整集合和跨目录离线评测 | `evaluation_multi.py`、`catalog_evaluation.py`、`reports/` | 区分首次留出成绩与使用该题集调优后的复测 |
| 测试、CI 与质量门禁 | `python/tests/`、`.github/workflows/shopping-agent.yml` | 本机测试通过可写；GitHub Actions 和 Python 3.12 须在实际跑通后再写 |

如果需要量化，写清楚**题集、分母、运行条件和时间**。例如第三合成目录首跑的完整集合为 14/18，同题修复后为 18/18；后一个数字是开发复测，不能称为未见数据泛化。参考 [PROGRESS.md](../PROGRESS.md) 和相应 JSON 报告核对原始结果。不要把来源 ID 匹配率写成回答逐句事实正确率。

## 投递前自检

1. 每个“实现”“优化”都能指向自己的代码、提交和测试，并能说清上游原本做了什么。
2. 每个数字都能复现，且写明是合成离线指标还是线上业务指标。
3. 只列实际用过的 Python、LangGraph、FastAPI、SQLite、Docker 等技术；没有运行过的组件不列。
4. 没有真实流量与可归因实验时，不写 CTR、GMV、QPS、P99、可用性或广告合规率的提升。
5. 仓库链接、项目日期、岗位角色和个人贡献与真实经历一致。
